# VideoHub v2.1.0

VideoHub 是一个“油猴统一入口 + 本机 yt-dlp”的多站点视频下载方案。

当前目标平台：

- YouTube
- Bilibili
- X / Twitter
- 小红书
- 抖音

## 为什么仍然采用本机 helper

纯油猴直接抓媒体 URL 在这些平台上都不够稳定。常见问题包括：

- DASH 音视频分离
- 临时签名 URL
- SPA 页面结构变化
- 登录态 / 风控 / Cookie
- HLS / m3u8
- 视频和音频需要 FFmpeg 合并
- 上游接口变化频繁

因此油猴只负责统一 UI，本机 helper 负责调用 yt-dlp。

## 1. 安装依赖

Python 3.10+：

```bash
python -m pip install -U "yt-dlp[default]"
```

另外建议系统安装：

- FFmpeg / ffprobe
- Deno（主要用于当前 YouTube 的 JavaScript challenge 支持）

FFmpeg 是 MP3 提取、字幕转换以及分离音视频合并的关键依赖。

## 2. 启动本地 helper

```bash
python videohub_helper.py
```

正常会看到：

```text
VideoHub Local Helper v2.0.0
监听地址: http://127.0.0.1:18765
```

保持这个终端窗口运行。

## 3. 安装油猴脚本

Tampermonkey：

1. 新建脚本。
2. 删除默认内容。
3. 粘贴 `videohub.user.js` 全部内容。
4. 保存。
5. 刷新支持的网站。

页面右下角应出现：

```text
↓ VideoHub
```

这个按钮在支持域名上始终显示，因此不会再因为某个平台的 SPA 页面识别变化而“完全找不到按钮”。

## 4. 使用

打开具体视频或帖子页面，点击右下角 `VideoHub`。

支持：

- 最佳画质视频
- MP3
- 仅字幕
- 视频同时保存字幕
- 可选“使用浏览器登录态”

默认保存目录：

```text
~/Downloads/VideoHub/
```

每个平台会进入自己的子目录。

## 浏览器登录态

默认关闭。

小红书、抖音、X、Bilibili 的部分内容可能要求登录态或触发平台风控。此时可以在 VideoHub 菜单中勾选：

```text
使用浏览器登录态（仅本机读取）
```

helper 会调用 yt-dlp 的 `--cookies-from-browser`。

浏览器类型在 `config.json` 中配置：

```json
{
  "browser": "chrome",
  "browser_profile": ""
}
```

例如可改成：

- `edge`
- `firefox`
- `brave`
- `chromium`

具体支持范围由当前 yt-dlp 决定。

注意：Cookie 只由本机 yt-dlp 读取，不通过网页发送到远程服务。本脚本不会使用 `document.cookie` 收集登录信息。

## 安全设计

本地 helper：

- 只监听 `127.0.0.1`
- 不提供 CORS
- 每次启动随机生成本地安全令牌
- 创建任务和查询状态都必须携带令牌
- 只允许白名单平台
- 只接受单视频 / 单帖子 URL
- 日志会去掉 URL query，避免小红书 `xsec_token` 等参数直接出现在终端错误信息中

## 平台稳定性

不同平台不能认为是同一稳定等级。

YouTube、Bilibili、X 有明确的 yt-dlp extractor，但平台更新仍可能临时导致失效。

抖音也有 yt-dlp extractor，但风控和接口变化会影响成功率。

小红书是最需要保守预期的平台之一：登录态、验证码、短链接校验和最高画质策略都可能变化。遇到问题优先更新 yt-dlp：

```bash
python -m pip install -U "yt-dlp[default]"
```

如果 stable 刚好落后于平台变化，可尝试 nightly：

```bash
python -m pip install -U --pre "yt-dlp[default]"
```

## 诊断

如果右下角没有按钮：

F12 -> Console 搜索：

```text
VideoHub
```

正常应出现：

```text
[VideoHub] v2.0.0 loaded
[VideoHub] platform=...
[VideoHub] button mounted successfully
```

如果按钮存在但下载失败：

1. 看油猴面板状态。
2. 看 `videohub_helper.py` 终端输出。
3. 更新 yt-dlp。
4. 必要时开启浏览器登录态。
5. 检查 FFmpeg。

## 范围边界

这个版本只处理单视频 / 单帖子下载，不做：

- 整个 UP 主 / 账号批量抓取
- 整个收藏夹批量抓取
- DRM 绕过
- 付费权限绕过
- 验证码绕过

请只下载你有权保存的内容，并遵守内容许可和平台规则。


## v2.1.0 字幕选择与修复

更新后需要重启 Python helper，并将新版 `videohub.user.js` 重新保存到 Tampermonkey，然后刷新视频页面。

1. 打开 VideoHub 面板，点击“加载 / 刷新可用字幕”。解析可能需要几十秒。
2. 勾选一种或多种字幕。列表标注人工、自动生成原文和自动翻译，并显示语言代码。
3. 点击“仅保存字幕”，或勾选“下载视频时同时保存字幕”后下载视频。

人工与自动字幕分别保存，文件名带 `manual` / `auto`，避免同语言互相覆盖。无 FFmpeg 时保留原字幕格式，有 FFmpeg 时转为 SRT。

未加载列表时仍支持原来的快捷下载：优先匹配配置中的语言，同一语言优先人工字幕或原文自动字幕（如 `en-orig`）；若没有匹配语言，尝试一条原文自动字幕。加载列表后必须明确勾选字幕。切换视频或浏览器登录态后需重新加载。

修复内容：逐项下载避免一种字幕失败阻断其他字幕；不再把“没有匹配语言且没有生成文件”报告为成功；字幕下载不再要求存在可下载视频格式；视频成功后字幕解析失败只报告警告。YouTube 429 仍最多重试一次，自动翻译字幕的限流无法保证消除。

本地回归检查：`python -m unittest -v test_subtitles`；脚本语法检查：`node --check videohub.user.js`。

## YouTube 播放列表批量下载（2.2.0）

1. 重启本地服务，并将更新后的 `videohub.user.js` 重新安装到 Tampermonkey，刷新 YouTube 页面。
2. 打开带 `list=` 参数的视频页或 `/playlist?list=...` 页面，点击 VideoHub →「加载 YouTube 播放列表」。
3. 全选或逐项勾选视频，选择「下载所选视频」或「仅下载所选字幕」。视频是否附带字幕由上方选项控制。
4. 字幕默认使用配置语言；在单视频页面加载并勾选字幕后，批量任务会沿用这些语言和来源。不同视频字幕可能不同，缺失时会报告失败或字幕警告。

每批最多 500 项，按列表顺序逐项执行，单项失败继续处理其余项，结束后显示成功、失败和字幕警告数量及异常条目地址。文件仍保存到原有 YouTube 下载目录，文件名包含视频 ID；列表中的私有、删除或受限视频可能下载失败。关闭或刷新页面不会停止已提交的任务，但当前界面暂不提供刷新后的任务恢复。

验证：`python -m unittest -q test_playlist test_subtitles`；`node --check videohub.user.js`。


### 代理设置与连接失败

在本地 `config.json` 中设置 `"proxy": "http://127.0.0.1:17891"`（端口须与自己的代理软件一致），然后重启本地服务。此配置供播放列表、字幕解析及所有媒体下载共用。省略 `proxy` 或设为 `null` 时继承环境变量/系统代理；设为 `""` 时直连。YouTube 在当前网络无法直连时仍需要可用代理。

若出现 `Unable to connect to proxy` / `WinError 10061`，先确认代理程序已启动及监听端口是否正确。此错误发生在连接代理阶段，更新 yt-dlp 或修改播放列表地址不能解决端口拒绝连接的问题。个人 `config.json` 已在 Git 忽略列表中。


### 批量字幕完整性（2.2.1）

批量字幕会针对每个视频重新查询可用轨道，保持所选语言和人工/自动来源；支持原文标签 `en-orig` / `en`、`zh-Hans` / `zh` 等匹配，不会把繁体中文或其他语言当成所选字幕。默认语言模式也可下载仅有人工原文字幕的视频。未提供所选语言/来源、没有字幕或限流失败的条目会显示具体原因；失败后继续下一项。执行时显示当前视频的字幕阶段，已处理条目逐项列出，结束后可重试失败或字幕不完整的条目。

使用新界面需重新安装 `videohub.user.js` 并刷新页面，后端改动需在当前任务结束后重启本地服务。无字幕的视频无法通过批量下载自动生成字幕。


### 下载面板（2.3.0）

面板按「下载范围 → 下载内容 → 任务状态」组织：先切换当前视频或播放列表，再选择视频、仅字幕或 MP3，最后点击底部主按钮。播放列表支持按标题搜索，搜索不会清空其他条目的勾选；「全选全部」作用于完整列表，旁边显示总计与已选数量。批量模式目前提供视频和字幕下载。

字幕语言、浏览器登录态与逐项结果分别折叠显示；字幕选择同时用于当前视频和批量任务。主按钮显示实际下载类型及批量数量，任务状态固定在面板底部。可通过右上角关闭按钮、Esc 或点击面板外关闭，关闭面板不会停止后台任务。界面使用 Shadow DOM 隔离宿主网页样式。

此次界面更新仅需重新安装 `videohub.user.js` 并刷新页面；如仍在下载，等当前任务结束再刷新。浏览器交互回归测试为 `node test_ui.cjs`（需要安装 Playwright，并有 Chrome 可用），测试使用模拟接口，不会创建真实下载任务；截图保存在 `.verification/ui/`。


### 语言与字幕来源选择（2.3.1）

选择「仅字幕」，或开启视频同时保存字幕后，在「字幕设置」中选择「自定义」。语言可多选中文（简体）、中文（繁体）和英文；来源可多选原始字幕（作者上传）、自动生成（语音识别原文）和自动翻译（平台翻译）。语言和来源按组合下载，例如「中文、英文 + 原始字幕」请求两种语言的作者字幕。

无需先查询当前视频即可设置批量字幕；「查看当前视频可用字幕」仅用于参考，不会清空选择，也不代表整张播放列表都具有这些字幕。缺失组合会逐项报告，自动生成与自动翻译严格区分。默认设置继续使用配置语言自动匹配可用字幕。

升级需同时重新安装脚本并在现有任务结束后重启本地服务；旧服务不支持类型细分时，界面会提示重启，防止错误下载字幕来源。


### 字幕缺失处理（2.3.2）

初始字幕选项为「中文 / 自动生成」。在字幕设置中可配置「所选语言或来源缺失时」：默认尝试中文自动生成字幕，也可选择仅报告缺失、不替代。替代只在字幕轨道缺失时生效，下载过程的网络错误不会被当作语言缺失；结果会注明实际使用了替代字幕。多个缺失组合使用同一条中文自动字幕时只下载一次。若中文自动字幕也不存在，则报告失败，不会改下自动翻译或其他语言。更新后需重新安装脚本并在当前任务结束后重启服务。
